# Verify the ISBN Reader in a browser

Run the checks below with the Playwright MCP (`mcp__playwright__*` tools; if they are deferred, load them with ToolSearch) and report pass/fail. Do not edit app code: report failures instead.

## Setup
1. Confirm the Playwright MCP is connected. If not, stop and tell the user to register it (`.mcp.json`) and check `/mcp`.
2. App server on http://localhost:8000: `curl -s http://localhost:8000/ | grep "<title>"` should show `ISBN Reader`. If so, reuse that server and never stop it. If the port is free, start `python3 -m http.server 8000` in the background from the project root and stop it when done. If the port serves something else, stop and report.
3. Save screenshots to `.playwright-mcp/` (gitignored), named `verify-<check>.png`.
4. Start from a clean state: on the app origin run `localStorage.clear()` (the Scanned list, Marked list and theme choice persist between runs), then reload.
5. ISBNs: when a check needs several books, read them from `test/fixtures/isbns.json` (`found` and `notFoundInOpenLibrary` are both just valid ISBNs now; `invalid` fail the check) instead of inventing ISBNs. The ISBNs written out in the checks below are entries from that file.
6. The app makes no network requests besides loading its own files (and `vendor/zxing-browser.min.js` after Scan). Record every request with `page.on('request', …)` for the whole run: any request to another host (for example openlibrary.org) is a failure, apart from links the test opens on purpose.
7. The Python dev server occasionally drops one module request (`ERR_CONNECTION_RESET`), which leaves the app dead on that load. If the page does nothing, reload once and retry before reporting a failure.

## Checks
Use `browser_run_code_unsafe` for anything that needs timing, request counting or page overrides. The search form is `#search`. A search is instant (nothing is fetched), so no waiting is needed.

1. **Card.** Search `9780747532699`. Expect status empty, a card (`.book`) with heading `ISBN 9780747532699`, a text field `.name-input` (placeholder "Назва книги (необов’язково)"), a mark button `.mark-toggle` (a direct child of the card, at its right edge: its right edge equals the right edge of the ✕ buttons in the Marked list, and its top edge is level with the top of the name block) showing ☆ (tooltip "Вибрати", `aria-label` "Вибрати", `aria-pressed="false"`), and, below the name block, a row `.link-row` of two big link buttons `.link-button` (Ereadian, Goodreads) that is centered across the card with a constant 16 px gap: each is 88 × 88 px and shows the site icon at 64 px (the PNG from `icons/`, loaded, natural width 128) with the site name underneath. Their links are `https://ereadian.com/search?q=9780747532699` and `https://www.goodreads.com/book/isbn/9780747532699` (both open in a new tab, `rel="noopener noreferrer"`, tooltip `<isbn> on <site>`). Check once in dark mode (`page.emulateMedia({ colorScheme: 'dark' })`) that both icons are clearly visible, and that keyboard focus on a button shows a 2 px outline. The old line "Look up this ISBN on …" is gone. **Language:** the interface is Ukrainian only (`<html lang="uk">`, title and heading "Сканер ISBN", buttons "Пошук" / "Сканувати" / "Безперервно" / "Стоп", the lists "Шукане" and "Вибране", Copy / Clear as "Копіювати" / "Очистити"); no visible English except the site names, `ISBN` and the `ISBN <number>` titles. All texts come from `src/strings.js` and `index.html`; check them at 360 px for wrapping. Check this at a desktop width and at 360 px (no sideways scroll). No rating, authors, cover or "More by…". The hash is `#isbn=9780747532699`, the Scanned list (open it with `#scanned summary`) holds one row `ISBN 9780747532699`, and no request went to another host. Repeat for a few other ISBNs from the list (including an ISBN-10 such as `080442957X`) and for a Ukrainian one: same shape.
2. **Typed name** (once). Type `My Ukrainian book` in the name field and press Enter: the heading becomes "My Ukrainian book" and so does the Scanned row; click Mark: the Marked entry has that title; change the name to `Renamed` and press Enter: the heading, the Scanned row and the Marked entry all change; reload and search the same ISBN again: the card shows "Renamed"; clear the field and press Enter: the heading is `ISBN <isbn>` again.
2a. **Lists open themselves.** With empty lists on a clean load, both `#scanned` and `#marked` are collapsed. The first search opens Scanned (not Marked), the first star opens Marked. If the user collapses a list by hand, later additions leave it collapsed. A load with non-empty lists shows them open.
2b. **Focus.** The ISBN field is not auto-focused: after a page load (with and without `#isbn=…` in the URL) `document.activeElement` is the body, and opening a book from the Scanned or Marked list does not focus the field either. A typed search (Search button or Enter) leaves the cursor in the field.
3. **Invalid ISBN.** Search `1234567890`. Expect status "Введіть дійсний ISBN-10 або ISBN-13.", an empty result area, nothing added to Scanned.
4. **Camera denied.** Reload the page. Expect `vendor/zxing-browser.min.js` was not requested on load (the camera and library must not start by themselves). Headless Chromium leaves the permission prompt pending, so simulate a denial before clicking Scan:
   `navigator.mediaDevices.getUserMedia = () => Promise.reject(new DOMException('Permission denied', 'NotAllowedError'))`.
   Click Scan. Expect status "Камера недоступна. Введіть ISBN вручну." (error style), `#scanner` hidden, the field and Search enabled, the button labelled "Сканувати", and the field focused.
5. **Deep links.** Load `http://localhost:8000/#isbn=9780747532699` and reload: the card for that ISBN appears, the field holds the ISBN, the hash is unchanged. Then search `9780141365466`: the hash becomes `#isbn=9780141365466`. `page.goBack()` shows the first card again with hash `#isbn=9780747532699`, the field filled, and `history.length` not increased by the Back. Then load `#isbn=1234567890` and reload: no search runs (empty result area, empty status, empty field).
6. **Scanned list (typed searches, capped at 1000).** Clear `localStorage`, reload, open the list (`#scanned summary`, title "Шукане (N)"). Empty: count 0, the empty-state text visible, Copy / Clear disabled. Then search 12 ISBNs in order: the first 11 entries of `found` in `test/fixtures/isbns.json`, with `invalid[0]` (`1234567890`, obvious nonsense) inserted as the 6th search.
   Expect in `#scanned-list li`: the count grows by one per real ISBN, stays the same after the nonsense ISBN (validation error, nothing added), and reaches 11 (there is no limit of 10 any more). Rows are newest first; each shows only the name, two small icon links (Ereadian, Goodreads) and a ☆/★ button (no ISBN text). `localStorage['isbn-reader.scanned']` holds the same ISBNs in the same order, and a reload restores them. Clicking the name of a row in Scanned or in Marked shows that book's card but does **not** move it in Scanned (a Marked book that is missing from Scanned is added at the top); Back/Forward and a reload with `#isbn=…` also leave the order alone. Only a new typed search or scan of an already listed book moves it to the top, with no duplicate. The star on a row marks the book (the row shows ★, Marked gains the book, the card's star flips if that book's card is shown), and clicking ★ unmarks it. Copy list gives "Скопійовано N книги/книг до буфера." (Ukrainian plural: 1 книга, 2–4 книги, 5+ книг) with `Title (ISBN)` per line; Clear (confirm "Очистити «Шукане» (N книг)? Вибране залишиться."; use `browser_click` and `browser_handle_dialog`: dismiss keeps the list, accept empties it) leaves Marked untouched. **Cap (a full list refuses):** with 1000 entries stored in `isbn-reader.scanned` (generate valid-shaped entries in the page, none with a real ISBN), a search for a new ISBN still shows its card, and `#list-warning` is visible between `#result` and the Scanned section with "Список «Шукане» заповнений (1000 книг), цю книгу не додано. Очистіть список, щоб додавати далі."; the list still has 1000 entries and does not contain the new ISBN. Searching an ISBN that is already listed moves it to the top and shows no warning; the warning also goes on the next search of a listed book, and when the list is cleared. With 1000 entries in `isbn-reader.marked`, the card's ☆ is refused: it stays ☆ and the warning says "Список «Вибране» заповнений (1000 книг), цю книгу не додано. Приберіть кілька книг або очистіть список, щоб додавати далі."; unmarking one entry hides the warning. **Migration:** with `localStorage['isbn-reader.recent']` set to `[{"isbn":"9780141365466","title":"Matilda"},{"isbn":1}]` and no `isbn-reader.scanned`, a reload shows one Scanned row "Matilda" (invalid entries dropped). **Corrupt storage:** set `localStorage['isbn-reader.scanned']` to `[null,5,{"isbn":1}]` and reload: the list is empty and there are no console errors; then search `9780747532699`: the card still renders and the stored value contains only valid entries (objects with string `isbn` and `title`).
7. **Theme toggle.** The button `#theme` cycles 🌓 Auto → ☀️ Light → 🌙 Dark → Auto. Use `page.emulateMedia({ colorScheme })` for the device setting and compare the computed `body` background: light `rgb(246, 246, 244)`, dark `rgb(27, 27, 26)` (if the palette in `style.css` changed, compare against the `--bg` values instead). Expect: in Auto (no `data-theme` attribute, nothing stored) the page follows the device live in both directions without a reload; one click gives "☀️ Світла", `data-theme="light"` and light even when the device is dark; the next click gives "🌙 Темна" and dark even when the device is light; a reload keeps Dark (`isbn-reader.theme` is `dark`); the next click returns to Auto, removes `isbn-reader.theme`, and follows the device again.
8. **Marked list.** Clear `localStorage`, reload, open the collapsed list (click `#marked summary`; its title is "Вибране (N)"). Empty: count 0, the empty-state text visible, Copy / Clear disabled. Search `9780141365466`: the card has the mark button (☆); click it: it shows ★ (tooltip "Вибрано (натисніть, щоб прибрати)", `aria-label` still "Вибрати", `aria-pressed="true"`), the list shows one entry (count 1, `localStorage['isbn-reader.marked']` has the ISBN). Search `9780747532699` and mark it: newest first. **Each list entry shows only** its name (`ISBN <isbn>`, or the typed one), two small icon-only links `.icon-link` (44 × 44 px, a 28 px icon, the image's `alt` is "Ereadian" / "Goodreads" (it names the link, and shows in the box if the icon fails to load: abort `**/icons/*.png` with `page.route` to see it), tooltip `<isbn> on <site>`; hrefs `https://ereadian.com/search?q=<isbn>` and `https://www.goodreads.com/book/isbn/<isbn>`) and a ✕ button (tooltip and `aria-label` "Прибрати з вибраного"): no authors, no separate ISBN text, links with `target="_blank"` and `rel="noopener noreferrer"`. Click the first entry's name: it runs that search (hash changes). Click ✕ on an entry: if its card is shown, the card's button flips back to ☆. Mark it again, then: Copy list gives status "Скопійовано 2 книги до буфера." and the clipboard text `Title (ISBN)` per line (grant clipboard permissions with `page.context().grantPermissions`). Clear shows a confirm dialog ("Очистити «Вибране» (2 книги)?"): the MCP intercepts dialogs, so click `#clear-marked` with `browser_click` and answer with `browser_handle_dialog` (dismiss: still 2 books; accept: empty, empty-state text back, card button ☆). **Layout** (desktop width and a phone width such as 360 px; check the rects of `li`, `.open` and `.row-actions`): the name is at the left edge and wraps when long, the links and the ✕ stay together as one group (`.row-actions`) at the right edge of the row (on a phone the group may sit under a long name, still right-aligned), and the page does not scroll sideways. A reload keeps whatever is marked. 9. **Scanning with a fake camera.** Headless Chromium has no camera, so inject `fake-camera.js` (next to this file): `Read` it and pass its arrow function to `page.evaluate`. Start from a clean `localStorage`; the checkbox `#keep-scanning` starts unticked (there is no Auto-mark option any more: scanned books go to Scanned, and only the ☆ marks them).
    - **Single scan, new book:** `window.__setBarcode('9780747532699')`, click Scan: the camera stops (scanner hidden, button "Сканувати"), the field holds the ISBN, the hash is set, the card `ISBN 9780747532699` is shown with its star (☆), the status is empty, the Scanned list holds the book (count 1) and Marked is empty.
    - **Single scan, repeat:** scan the same ISBN again after ~3.2 s (the duplicate window): status "Вже в «Шуканому»: ISBN 9780747532699", still one Scanned row. A *typed* search of an already scanned ISBN shows the card with no message.
    - **Keep scanning:** tick Keep scanning, set the barcode to `9780140328721`, click Scan: at once the Scanned list holds that ISBN at the top, the status is "Додано: ISBN 9780140328721"; the camera stays on (button "Стоп"), the field, Search, the checkbox and both Clear buttons are disabled (the names in the lists too), the Scanned list (collapsed while it was empty) opened by itself when that first book arrived, and the previous card is gone. Keep the same barcode in view for ~4.5 s: still one new row. Show `9780606186513`: another row on top. Show a non-book EAN-13 (`4006381333931`): status "Це не ISBN книги.", nothing added; show `null` (no barcode): the message clears within a couple of seconds. Show the first book again, but first show no barcode (`null`) for ~3.5 s (a book seen again within 3 s of its last sighting counts as the same sighting and is ignored by design): status "Вже в «Шуканому»: ISBN 9780140328721", count unchanged, and that row moves to the top. That message appears once, stays while the barcode stays in view (also past the 3 s duplicate window) and is cleared about a second after the barcode leaves (`null`). A book that was just added keeps its "Додано: …" message while it stays in view (it must not flip to "Вже в «Шуканому»"). Click Stop: scanner hidden, button "Сканувати", field and checkbox enabled. Nothing is marked by scanning; starring a scanned row marks it.
    - **Full Scanned list:** with 1000 entries stored, a scan (single or Keep scanning) of a new book shows the card (single) or the status "Не додано: … (список «Шукане» заповнений)" in error style (Keep scanning), the warning is visible, nothing is added, and the page flashes red with a 330 Hz beep (no further beeps while the barcode stays in view).
    - **Beep and flash:** both happen when the camera reads the barcode (a higher tone and an amber page flash for a new book, a lower tone and a blue flash for one that is already in Scanned). The sound itself cannot be heard headless (say "not verified"), but the code path can be checked: wrap `AudioContext.prototype.createOscillator` with an init script that records `frequency.value`, and watch the class list of `#snap` (`flash`, plus `again` for a marked book). Expect one 880 Hz record and an amber flash for a new book, 520 Hz and `again` for a marked one, and nothing for a non-book barcode or a repeated sighting inside the duplicate window.
