# Verify the ISBN Reader in a browser

Run the checks below with the Playwright MCP (`mcp__playwright__*` tools; if they are deferred, load them with ToolSearch) and report pass/fail. Do not edit app code: report failures instead.

## Setup
1. Confirm the Playwright MCP is connected. If not, stop and tell the user to register it (`.mcp.json`) and check `/mcp`.
2. App server on http://localhost:8000: `curl -s http://localhost:8000/ | grep "<title>"` should show `ISBN Reader`. If so, reuse that server and never stop it. If the port is free, start `python3 -m http.server 8000` in the background from the project root and stop it when done. If the port serves something else, stop and report.
3. Save screenshots to `.playwright-mcp/` (gitignored), named `verify-<check>.png`.
4. Start from a clean state: on the app origin run `localStorage.clear()` (recent searches and the theme choice persist between runs), then reload.
5. ISBNs: when a check needs several books, read them from `test/fixtures/isbns.json` (`found` and `notFoundInOpenLibrary` are both just valid ISBNs now; `invalid` fail the check) instead of inventing ISBNs. The ISBNs written out in the checks below are entries from that file.
6. The app makes no network requests besides loading its own files (and `vendor/zxing-browser.min.js` after Scan). Record every request with `page.on('request', …)` for the whole run: any request to another host (for example openlibrary.org) is a failure, apart from links the test opens on purpose.
7. The Python dev server occasionally drops one module request (`ERR_CONNECTION_RESET`), which leaves the app dead on that load. If the page does nothing, reload once and retry before reporting a failure.

## Checks
Use `browser_run_code_unsafe` for anything that needs timing, request counting or page overrides. The search form is `#search`. A search is instant (nothing is fetched), so no waiting is needed.

1. **Card.** Search `9780747532699`. Expect status empty, a card (`.book`) with heading `ISBN 9780747532699`, a text field `.name-input` (placeholder "Name this book (optional)"), a mark button `.mark-toggle` (a direct child of the card, at its right edge: its right edge equals the right edge of the ✕ buttons in the Marked list, and its top edge is level with the top of the name block) showing ☆ (tooltip "Mark", `aria-label` "Mark", `aria-pressed="false"`), and the line "Look up this ISBN on Ereadian or Goodreads." whose links are `https://ereadian.com/search?q=9780747532699` and `https://www.goodreads.com/book/isbn/9780747532699` (both open in a new tab, `rel="noopener noreferrer"`). No rating, authors, cover or "More by…". The hash is `#isbn=9780747532699`, one chip `ISBN 9780747532699` appears, and no request went to another host. Repeat for a few other ISBNs from the list (including an ISBN-10 such as `080442957X`) and for a Ukrainian one: same shape.
2. **Typed name** (once). Type `My Ukrainian book` in the name field and press Enter: the heading becomes "My Ukrainian book" and so does the chip; click Mark: the Marked entry has that title; change the name to `Renamed` and press Enter: the heading, the chip and the Marked entry all change; reload and search the same ISBN again: the card shows "Renamed"; clear the field and press Enter: the heading is `ISBN <isbn>` again.
3. **Invalid ISBN.** Search `1234567890`. Expect status "Please enter a valid ISBN-10 or ISBN-13.", an empty result area, no chip.
4. **Camera denied.** Reload the page. Expect `vendor/zxing-browser.min.js` was not requested on load (the camera and library must not start by themselves). Headless Chromium leaves the permission prompt pending, so simulate a denial before clicking Scan:
   `navigator.mediaDevices.getUserMedia = () => Promise.reject(new DOMException('Permission denied', 'NotAllowedError'))`.
   Click Scan. Expect status "Camera unavailable. Type the ISBN instead." (error style), `#scanner` hidden, the field and Search enabled, the button labelled "Scan", and the field focused.
5. **Deep links.** Load `http://localhost:8000/#isbn=9780747532699` and reload: the card for that ISBN appears, the field holds the ISBN, the hash is unchanged. Then search `9780141365466`: the hash becomes `#isbn=9780141365466`. `page.goBack()` shows the first card again with hash `#isbn=9780747532699`, the field filled, and `history.length` not increased by the Back. Then load `#isbn=1234567890` and reload: no search runs (empty result area, empty status, empty field).
6. **Recent searches (chips, max 10).** Clear `localStorage`, reload, then search 12 ISBNs in order: the first 11 entries of `found` in `test/fixtures/isbns.json`, with `invalid[0]` (`1234567890`, obvious nonsense) inserted as the 6th search.
   Expect in `#recent .chip`: the count grows 1 to 5, stays 5 after the nonsense ISBN (validation error, no chip), grows to 10 after the 10th real ISBN, and stays 10 after the 11th, which drops the oldest chip. Chips are newest first and each chip's `title` attribute is its ISBN. `localStorage['isbn-reader.recent']` holds the same 10 ISBNs in the same order, and a reload restores the same chips. Clicking the oldest chip shows its card again and moves it to the front with no duplicates (still 10). **Corrupt storage:** set `localStorage['isbn-reader.recent']` to `[null,5,{"isbn":1}]` and reload: no chips are shown (`#recent` hidden) and there are no console errors. Then search `9780747532699`: the card must still render, one chip appears, and the stored value afterwards contains only valid entries (objects with string `isbn` and `title`).
7. **Theme toggle.** The button `#theme` cycles 🌓 Auto → ☀️ Light → 🌙 Dark → Auto. Use `page.emulateMedia({ colorScheme })` for the device setting and compare the computed `body` background: light `rgb(246, 246, 244)`, dark `rgb(27, 27, 26)` (if the palette in `style.css` changed, compare against the `--bg` values instead). Expect: in Auto (no `data-theme` attribute, nothing stored) the page follows the device live in both directions without a reload; one click gives "☀️ Light", `data-theme="light"` and light even when the device is dark; the next click gives "🌙 Dark" and dark even when the device is light; a reload keeps Dark (`isbn-reader.theme` is `dark`); the next click returns to Auto, removes `isbn-reader.theme`, and follows the device again.
8. **Marked list.** Clear `localStorage`, reload, open the collapsed list (click `#marked summary`; its title is "Marked (N)"). Empty: count 0, the empty-state text visible, Copy / Download / Clear disabled. Search `9780141365466`: the card has the mark button (☆); click it: it shows ★ (tooltip "Marked (click to unmark)", `aria-label` still "Mark", `aria-pressed="true"`), the list shows one entry (count 1, `localStorage['isbn-reader.marked']` has the ISBN). Search `9780747532699` and mark it: newest first. **Each list entry shows only** its name (`ISBN <isbn>`, or the typed one), an "Ereadian" link, a "Goodreads" link (`https://www.goodreads.com/book/isbn/<isbn>`) and a ✕ button (tooltip and `aria-label` "Unmark"): no authors, no separate ISBN text, links with `target="_blank"` and `rel="noopener noreferrer"`. Click the first entry's name: it runs that search (hash changes). Click ✕ on an entry: if its card is shown, the card's button flips back to ☆. Mark it again, then: Copy list gives status "Copied 2 books to the clipboard." and the clipboard text `Title (ISBN)` per line (grant clipboard permissions with `page.context().grantPermissions`); Download JSON downloads `isbn-marked.json` with both ISBNs. Clear shows a confirm dialog ("Unmark all 2 books?"): the MCP intercepts dialogs, so click `#clear-marked` with `browser_click` and answer with `browser_handle_dialog` (dismiss: still 2 books; accept: empty, empty-state text back, card button ☆). **Layout** (desktop width and a phone width such as 360 px; check the rects of `li`, `.open` and `.row-actions`): the name is at the left edge and wraps when long, the links and the ✕ stay together as one group (`.row-actions`) at the right edge of the row (on a phone the group may sit under a long name, still right-aligned), and the page does not scroll sideways. A reload keeps whatever is marked. An entry saved by an older version (set `localStorage['isbn-reader.marked']` to `[{"isbn":"9780141365466","title":"Matilda","authors":["Roald Dahl"]}]`, reload) shows just "Matilda" and the links.
9. **Scanning with a fake camera.** Headless Chromium has no camera, so inject `fake-camera.js` (next to this file): `Read` it and pass its arrow function to `page.evaluate`. Start from a clean `localStorage`; the checkboxes `#auto-mark` and `#keep-scanning` start unticked, and "Keep scanning" is disabled until "Auto-mark" is ticked (unticking Auto-mark unticks it again). Ticking Auto-mark is remembered across a reload (`localStorage['isbn-reader.automark']` is `1`).
    - **Single scan, Auto-mark off:** `window.__setBarcode('9780747532699')`, click Scan: the camera stops (scanner hidden, button "Scan"), the field holds the ISBN, the hash is set, the card `ISBN 9780747532699` is shown **with the mark button**, and nothing is marked.
    - **Single scan, Auto-mark on:** tick Auto-mark, scan `9780141365466`: the camera stops, the card is shown **without the mark button**, status "Marked: ISBN 9780141365466", the list holds it. Scan it again: status "Already marked: ISBN 9780141365466", still one entry. A *typed* search for `9780747532699` with Auto-mark on shows the card **with** its mark button and marks nothing.
    - **Keep scanning:** tick Keep scanning, set the barcode to `9780140328721`, click Scan: at once the list holds that ISBN, the status is "Marked: ISBN 9780140328721" and `#recent` shows a chip for it (every scanned book gets a chip, newest first, also when it was already marked: its chip moves to the front); the camera stays on (button "Stop"), the field, Search and both checkboxes are disabled, the list is opened automatically, and the previous card is gone. Keep the same barcode in view for ~4.5 s: still one entry. Show `9780606186513`: another entry. Show a non-book EAN-13 (`4006381333931`): status "That barcode isn't a book ISBN.", nothing added; show `null` (no barcode): the message clears within a couple of seconds. Show the first book again, but first show no barcode (`null`) for ~3.5 s (a book seen again within 3 s of its last sighting counts as the same sighting and is ignored by design): status "Already marked: ISBN 9780140328721", count unchanged. That message appears once, stays while the barcode stays in view (also past the 3 s duplicate window) and is cleared about a second after the barcode leaves (`null`). A book that was just marked keeps its "Marked: …" message while it stays in view (it must not flip to "Already marked"). Click Stop: scanner hidden, button "Scan", field and checkboxes enabled.
    - **Beep and flash:** both happen when the camera reads the barcode (a higher tone and an amber page flash for a book that is not marked yet, a lower tone and a blue flash for one that is). The sound itself cannot be heard headless (say "not verified"), but the code path can be checked: wrap `AudioContext.prototype.createOscillator` with an init script that records `frequency.value`, and watch the class list of `#snap` (`flash`, plus `again` for a marked book). Expect one 880 Hz record and an amber flash for a new book, 520 Hz and `again` for a marked one, and nothing for a non-book barcode or a repeated sighting inside the duplicate window.
10. **Console and network.** Collect console errors across the whole run (`browser_console_messages` with `all: true`, level error). Only this is expected: the logged `Could not start the scanner: NotAllowedError` (check 4). Anything else counts as a failure, as does any request to a host other than localhost (the recorded requests from the setup).

Optional (skip when offline): open `https://www.goodreads.com/book/isbn/9780747532699` and `https://ereadian.com/search?q=9786171299412` once to confirm the links still lead somewhere sensible (a Goodreads book page; Ereadian "1 книжка"). Keep this to a couple of page loads.

## Report
End with one table: check, result (pass / fail / not run), notes and screenshot path. State plainly what could not run and why. Close the browser (`browser_close`), stop the server only if you started it, and do not commit anything.
