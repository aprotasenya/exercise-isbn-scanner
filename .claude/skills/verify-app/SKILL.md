# Verify the ISBN Reader in a browser

Run the checks below with the Playwright MCP (`mcp__playwright__*` tools; if they are deferred, load them with ToolSearch) and report pass/fail. Do not edit app code: report failures instead.

## Setup
1. Confirm the Playwright MCP is connected. If not, stop and tell the user to register it (`.mcp.json`) and check `/mcp`.
2. App server on http://localhost:8000: `curl -s http://localhost:8000/ | grep "<title>"` should show `ISBN Reader`. If so, reuse that server and never stop it. If the port is free, start `python3 -m http.server 8000` in the background from the project root and stop it when done. If the port serves something else, stop and report.
3. Save screenshots to `.playwright-mcp/` (gitignored), named `verify-<check>.png`.
4. Start from a clean state: on the app origin run `localStorage.clear()` (recent searches and the theme choice persist between runs), then reload.
5. ISBNs: when a check needs several books, read them from `test/fixtures/isbns.json` (`found`, `notFoundInOpenLibrary`, `invalid`) instead of inventing ISBNs. The ISBNs written out in the checks below are entries from that file.
6. The Python dev server occasionally drops one module request (`ERR_CONNECTION_RESET`), which leaves the app dead on that load. If the page does nothing, reload once and retry before reporting a failure.

## Checks
Use `browser_run_code_unsafe` for anything that needs timing, request counting or page overrides. Assert shape, not exact numbers (ratings and "other books" can change). The search form is `#search`; wait for `#isbn` to be enabled again before the next search.

1. **Found book.** Search `9780747532699`. Expect a card titled "Harry Potter and the Philosopher's Stone", an author line, a rating line (`★ …`), a "More by J. K. Rowling" list with up to 5 items, and the line "Search this ISBN on Ereadian." whose link is `https://ereadian.com/search?q=9780747532699` (opens in a new tab).
2. **Not found.** For every entry in `notFoundInOpenLibrary` (all Ukrainian books that Ereadian has and Open Library lacks), search its ISBN. Expect status "Not found in Open Library." (plain, not error style) and a **card** (it is always shown, so the book can be marked): heading `ISBN <isbn>`, the line "Not found in Open Library.", no rating line, no "More by…" list, a "Mark" button, and the line "Search this ISBN on Ereadian." with the link `https://ereadian.com/search?q=<isbn>`. A chip is added to `#recent` for it too (title `ISBN <isbn>`, or the typed name), so the chip count grows by one per new ISBN; renaming the book on its card renames the chip. The card also has a text field `.name-input` (placeholder "Name this book (optional)"). **Typed name** (once, for the first entry): type `My Ukrainian book` and press Enter: the heading becomes "My Ukrainian book"; click Mark: the Marked entry has that title; change the name to `Renamed` and press Enter: the heading and the Marked entry both change; reload and search the same ISBN again: the card shows "Renamed"; clear the field and press Enter: the heading is `ISBN <isbn>` again. Found books (e.g. Matilda) have no such field.
3. **Invalid ISBN.** Count Open Library requests with `page.on('request', …)`, then search `1234567890`. Expect status "Please enter a valid ISBN-10 or ISBN-13.", an empty result area, and zero requests to openlibrary.org.
4. **Controls lock during a search.** `page.route('**/openlibrary.org/**', …)` delaying each request ~1.5 s; submit `9780747532699`; after ~300 ms expect `#isbn`, the Search button and `#scan` all disabled and status "Searching…"; after the card appears expect all three enabled. Remove the route afterwards (`page.unrouteAll({ behavior: 'wait' })`).
5. **Camera denied.** Reload the page. Expect `vendor/zxing-browser.min.js` was not requested on load (the camera and library must not start by themselves). Headless Chromium leaves the permission prompt pending, so simulate a denial before clicking Scan:
   `navigator.mediaDevices.getUserMedia = () => Promise.reject(new DOMException('Permission denied', 'NotAllowedError'))`.
   Click Scan. Expect status "Camera unavailable. Type the ISBN instead." (error style), `#scanner` hidden, the field and Search enabled, the button labelled "Scan", and the field focused.
6. **Deep links.** Load `http://localhost:8000/#isbn=9780747532699` and reload: the card for that book appears, the field holds the ISBN, the hash is unchanged. Then search `9780141365466` (Matilda): the hash becomes `#isbn=9780141365466`. `page.goBack()` shows the Harry Potter card again with hash `#isbn=9780747532699`, the field filled, and `history.length` not increased by the Back. Then load `#isbn=1234567890` and reload: no search runs (empty result area, empty status, empty field). Finally **Back during a search**: with Open Library responses delayed ~1.5 s (as in check 4), open `#isbn=9780747532699` and wait for its card, search `9780141365466` (Matilda), and press Back about 300 ms later while Matilda is still loading. Expect that Matilda's card never appears: once the delayed responses finish the page shows the Harry Potter card, the hash is `#isbn=9780747532699`, the field holds that ISBN, the controls are enabled again, and Matilda is not in the chips (on a clean `localStorage`).
7. **Recent searches (chips, max 10).** Clear `localStorage`, reload, then search 12 ISBNs in order: the first 11 entries of `found` in `test/fixtures/isbns.json`, with `invalid[0]` (`1234567890`, obvious nonsense) inserted as the 6th search. The first entry is Harry Potter, the 2nd Matilda, the 11th Adventures of Huckleberry Finn.
   Expect in `#recent .chip`: the count grows 1 to 5, stays 5 after the nonsense ISBN (validation error, no chip), grows to 10 after the 10th real book, and stays 10 after the 11th, which drops the oldest chip (Harry Potter). Chips are newest first (Huckleberry Finn … Matilda) and each chip's `title` attribute is its ISBN. `localStorage['isbn-reader.recent']` holds the same 10 ISBNs in the same order, and a reload restores the same chips. Clicking the oldest chip (Matilda) shows its card again and moves it to the front with no duplicates (still 10). If one of these ISBNs stops resolving in Open Library, report which one instead of silently swapping it. **Corrupt storage:** set `localStorage['isbn-reader.recent']` to `[null,5,{"isbn":1}]` and reload: no chips are shown (`#recent` hidden) and there are no console errors. Then search `9780747532699`: the card must still render, one chip appears, and the stored value afterwards contains only valid entries (objects with string `isbn` and `title`).
8. **Theme toggle.** The button `#theme` cycles 🌓 Auto → ☀️ Light → 🌙 Dark → Auto. Use `page.emulateMedia({ colorScheme })` for the device setting and compare the computed `body` background: light `rgb(246, 246, 244)`, dark `rgb(27, 27, 26)` (if the palette in `style.css` changed, compare against the `--bg` values instead). Expect: in Auto (no `data-theme` attribute, nothing stored) the page follows the device live in both directions without a reload; one click gives "☀️ Light", `data-theme="light"` and light even when the device is dark; the next click gives "🌙 Dark" and dark even when the device is light; a reload keeps Dark (`isbn-reader.theme` is `dark`); the next click returns to Auto, removes `isbn-reader.theme`, and follows the device again.
9. **Marked list.** Clear `localStorage`, reload, open the collapsed list (click `#marked summary`; its title is "Marked (N)"). Empty: count 0, the empty-state text visible, Copy / Download / Clear disabled. Search `9780141365466` (Matilda): the card has a button "Mark"; click it: it says "Unmark", the list shows Matilda (count 1, `localStorage['isbn-reader.marked']` has her ISBN). Search `9780747532699` (Harry Potter) and mark it: newest first (Harry Potter, then Matilda). Click Matilda's title in the list: it runs that search (hash `#isbn=9780141365466`). Click "Unmark" on Matilda in the list: the card's button flips back to "Mark". Mark her again, then: Copy list gives status "Copied 2 books to the clipboard." and the clipboard text `Author — Title (ISBN)` per line (grant clipboard permissions with `page.context().grantPermissions`); Download JSON downloads `isbn-marked.json` with both ISBNs. Clear shows a confirm dialog ("Unmark all 2 books?"): the MCP intercepts dialogs, so click `#clear-marked` with `browser_click` and answer with `browser_handle_dialog` (dismiss: still 2 books; accept: empty, empty-state text back, button "Mark"). A reload keeps whatever is marked. Also mark a not-found book (`9786171299412`): its list entry is titled `ISBN 9786171299412`. After the name and ISBN, every list entry has an "Ereadian" link to `https://ereadian.com/search?q=<isbn>` (new tab, `rel="noopener noreferrer"`).
10. **Scanning with a fake camera.** Headless Chromium has no camera, so inject `fake-camera.js` (next to this file): `Read` it and pass its arrow function to `page.evaluate`. Start from a clean `localStorage`; the checkboxes `#auto-mark` and `#keep-scanning` start unticked, and "Keep scanning" is disabled until "Auto-mark" is ticked (unticking Auto-mark unticks it again). Ticking Auto-mark is remembered across a reload (`localStorage['isbn-reader.automark']` is `1`).
    - **Single scan, Auto-mark off:** `window.__setBarcode('9780747532699')`, click Scan: the camera stops (scanner hidden, button "Scan"), the field holds the ISBN, the hash is set, the Harry Potter card is shown **with a "Mark" button**, and nothing is marked.
    - **Single scan, Auto-mark on:** tick Auto-mark, scan `9780141365466`: the camera stops, the Matilda card is shown **without a Mark button**, status "Marked: Matilda", the list holds Matilda. Scan it again: status "Already marked: Matilda", still one entry. A *typed* search for `9780747532699` with Auto-mark on shows the card **with** its Mark button and marks nothing. Scan a not-found ISBN (`9786171299412`): the card `ISBN 9786171299412` is shown without a Mark button and the list gains that entry.
    - **Keep scanning:** tick Keep scanning, set the barcode to `9780140328721`, click Scan: within a few seconds the list holds Fantastic Mr. Fox, the status is "Marked: Fantastic Mr. Fox" and `#recent` shows a chip for it (every scanned book gets a chip, newest first, also when it was already marked: its chip moves to the front); the camera stays on (button "Stop"), the field, Search and both checkboxes are disabled, the list is opened automatically, and the previous card is gone. Keep the same barcode in view for ~4.5 s: still one entry. Show `9780606186513`: another entry. Show a non-book EAN-13 (`4006381333931`): status "That barcode isn't a book ISBN.", nothing added; show `null` (no barcode): the message clears within a couple of seconds. Show Fantastic Mr. Fox again, but first show no barcode (`null`) for ~3.5 s (a book seen again within 3 s of its last sighting counts as the same sighting and is ignored by design): status "Already marked: Fantastic Mr. Fox", count unchanged. That message follows the same rule as the not-a-book one: it appears once, stays while the barcode stays in view (also past the 3 s duplicate window) and is cleared about a second after the barcode leaves (`null`). A book that was just marked keeps its "Marked: …" message while it stays in view (it must not flip to "Already marked"). **Failed lookup:** with Open Library requests aborted (`page.route('**/openlibrary.org/**', (r) => r.abort())`), show a book that is not marked yet: status "Could not look up <isbn>. Keep it in view to retry.", nothing marked; remove the route (`unrouteAll`) and keep the barcode in view: within about 3 s it retries and the book is marked. **Stop during a lookup:** with Open Library responses delayed ~1.5 s, show a new book and click Stop right away: the book is still marked and gets its chip, but the status line stays empty and no beep is recorded after Stop. Click Stop: scanner hidden, button "Scan", field and checkboxes enabled.
    **Beep:** it sounds when the camera reads the barcode, not when the lookup finishes (a higher tone for a book that is not marked yet, a lower one for one that is). The sound itself cannot be heard headless (say "not verified"), but the timing can be: wrap `AudioContext.prototype.createOscillator` with an init script that records `frequency.value` and the time, delay Open Library ~3 s as in check 4, scan a new book (single and Keep scanning, Auto-mark on and off) and expect one 880 Hz record well before the delayed response arrives; scanning a marked book gives 520 Hz. A non-book barcode and a repeated sighting inside the duplicate window record nothing new.
11. **Console.** Collect console errors across the whole run (`browser_console_messages` with `all: true`, level error). Only these are expected: 404 for `openlibrary.org/isbn/<unknown ISBN>.json` (checks 2, 9 and 10), and the logged `Could not start the scanner: NotAllowedError` (check 5). A `favicon.ico` 404 is no longer expected (the icon is inline), so it counts as a failure, as does anything else.

Optional (skip when offline): open `https://ereadian.com/search?q=<isbn>` for the first two `notFoundInOpenLibrary` entries and expect "1 книжка" each; `9780000000002` (it exists in Open Library, so it only serves as an Ereadian nonsense check) should give "0 книжок". Keep this to a couple of page loads.

## Report
End with one table: check, result (pass / fail / not run), notes and screenshot path. State plainly what could not run and why. Close the browser (`browser_close`), stop the server only if you started it, and do not commit anything.
