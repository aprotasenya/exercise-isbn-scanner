# ISBN Reader

Minimal web page: enter or scan (camera) an ISBN, or type a title, get a card with links to look it up on Ereadian and Goodreads. Every ISBN lands in a "Scanned" list, and the ones the user stars go to a "Marked" list (a shopping companion). The only book data is an optional name and cover from a tiny lookup service (`worker/`, reads Goodreads); without it a book is its ISBN or the name the user typed. Vanilla JS ES modules, no build step.

## Commands
- Run: `python3 -m http.server 8000`, then open http://localhost:8000 (ES modules don't load over `file://`)
- Test: `npm test` (Node's built-in `node:test`, no network; covers `worker/` too)
- Lookup service: `worker/` (Cloudflare Worker, deploy steps in `worker/README.md`); its address goes in `LOOKUP_URL` in `src/lookup.js`, empty = lookup off
- Tests and browser checks that need several ISBNs use `test/fixtures/isbns.json` (valid real ISBNs and invalid ones); add new ones there instead of inventing them
- Verify UI changes in a real browser with `/verify-app` (needs the Playwright MCP from `.mcp.json`)
- Hook (`.claude/settings.json`): after edits to JS in `src/` or `test/`, `node --check` and `npm test` run automatically; a failure is reported back (exit code 2)

Ideas that are not in the current work go to `BACKLOG.md`.

## Constraints
- The interface is Ukrainian only (no language toggle): fixed text is written in `index.html`, every message built in code is in `src/strings.js` (Ukrainian plurals via `plural()`). The lists are «Шукане» (code: `scanned`) and «Вибране» (code: `marked`). Keep new texts concise.
- The app's only network calls are to our own worker, in `src/lookup.js`: the lookup (`GET <LOOKUP_URL>/lookup?isbn=…`), which reads the Goodreads page's JSON-LD and answers `{title, series, author, rating, image}`). and for a title typed into the field (anything that does not look like an ISBN, so "1984" is a title) `GET /search?q=…` (up to 5 candidates from Goodreads' search-as-you-type, shown as a pick list) and `GET /book?id=…` (the ISBN and details of the picked edition: the details are stored like a lookup's answer, so the picked book needs no second lookup, and the picked title names the book if the details are missing). A book found by title has its site links search instead of using the ISBN: Ereadian for the title alone (its search misses a book when an author is spelled differently there), Goodreads for the title and author (both taken from the candidate), because Goodreads' edition may not be the one in hand; a later search or scan by that ISBN goes back to ISBN links. The lookup by ISBN runs in the background after the card is shown, once per ISBN per page load, 10 s timeout per try, no retries except after a 429 from the worker (it waits 5 s and asks again, up to 3 times; the card's spinner runs the whole time), and the request carries the answer's shape version (`&v=6`, with `v6` in the worker) so the browser's HTTP cache never serves an older shape; every failure is silent, and the app must keep working fully without it (empty `LOOKUP_URL`). Open Library and Google Books stay out, and don't add a key or `config.js` without being asked. A found title only replaces the default `ISBN <number>`, never a typed name or an older stored title. The card shows what it found (`src/details.js`): the cover (an `<img>` with empty `alt`, removed if it fails to load; https only), the title without its trailing brackets, the rating as the accent (★ value, count), and the series (a Goodreads search for its name) and the first author (their Goodreads page) as links. Every field is validated in `cleanAnswer` before it is stored or rendered. The only other call is the anonymous usage stats (`src/stats.js`): `POST <LOOKUP_URL>/event`, a batch sent with `sendBeacon` as `text/plain` (no preflight) when the page is hidden or after 30 s, fire-and-forget, queue capped at 50, no retries, off when `LOOKUP_URL` is empty or the browser sends Do Not Track. It carries only a random per-browser id and short words or numbers from the fixed list in `worker/events.js` (device and browser family, scan results and timings, lookup outcomes, which features are used), never an ISBN, title or name; a new event needs its name and fields added there too, or the worker drops it. The id is shown at the bottom of the page (`#stats-note`). The developer's own use is flagged `dev`: `#dev` in the address sets it for good, `#nodev` clears it, localhost is always dev; every query on the stats leaves `dev = 1` out.
- Ereadian and Goodreads are link-only (`src/links.js`), shown as their icons (saved in `icons/`, see its README; never fetched at runtime, since their servers send no CORS headers): their pages can't be read from the browser and Ukrainian stores (Yakaboo, Rozetka) block scripts (403), so don't scrape them. The user can name a book by tapping its title on the card.
- Render user-supplied text (typed names, stored lists) only via `textContent`, never `innerHTML`.
- Keep it minimal: no frameworks, bundlers or npm dependencies. The one exception is the vendored `@zxing/browser` for barcode scanning (`vendor/`, see its README), loaded lazily only when Scan is pressed.
- State lives in the URL and in `localStorage`: `#isbn=<isbn>` deep-links a search (Back/Forward re-run it), `isbn-reader.scanned` holds every searched or scanned book (newest first), `isbn-reader.marked` the "Marked" list (the ☆ on a card or a Scanned row); a row shows the book's rating (★ value) in place of the lookup spinner once the lookup is over, `isbn-reader.search` the title and author a book was found by (its links search for them), `isbn-reader.names` names the user typed for books (tap the title on the card to edit it; empty goes back to the found title, or `ISBN <number>`), `isbn-reader.meta` what the lookup found (a cache, capped at 1000; entries carry a version `v`, an older one is shown but asked again), `isbn-reader.sort` each list's order (`date` = the list's own order, `name` А–Я, `rating`; changed from the ⇅ button in the list header; `src/sort.js`; a book whose lookup is still running stays on top until it ends), `isbn-reader.id` the random id for the usage stats, `isbn-reader.dev` the developer flag, `isbn-reader.theme` a light/dark override (absent = follow the device, via the theme button). Both lists hold at most 1000 books; a full list refuses new ones (the card is still shown, with a warning between it and the lists) and they share one list view (`src/listView.js`) and one store (`src/bookList.js`). Storage can be blocked, full or corrupt: reading it must never throw or stop the page from rendering.
- The scanner asks the camera for up to 1920x1080 and continuous focus (`VIDEO` in `src/scanner.js`, all `ideal`) and tries a frame every 250 ms; the preview stays invisible until its picture has stopped changing size for 300 ms (`revealWhenSteady`: an iPhone shows the first frames at the wrong size and place, then corrects them, so the picture jumps): without that a phone gives 480x640 and dim-light scans fail; the numbers come from `bench.html` (not linked from the app; its results stay in the browser, and "hold 5 s" gives the share of frames decoded). A native `BarcodeDetector` and zxing-cpp (WebAssembly) were benched against this on an iPhone and an Android phone and were not better, so there is only zxing-js.
- The camera must never start automatically, and the manual ISBN field must keep working when the camera is denied or unavailable. Camera access needs `localhost` or https.
