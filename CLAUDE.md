# ISBN Reader

Minimal web page: enter or scan (camera) an ISBN, get a card with links to look it up on Ereadian and Goodreads. Every ISBN lands in a "Scanned" list, and the ones the user stars go to a "Marked" list (a shopping companion). The only book data is an optional name and cover from a tiny lookup service (`worker/`, reads Goodreads); without it a book is its ISBN or the name the user typed. Vanilla JS ES modules, no build step.

## Commands
- Run: `python3 -m http.server 8000`, then open http://localhost:8000 (ES modules don't load over `file://`)
- Test: `npm test` (Node's built-in `node:test`, no network; covers `worker/` too)
- Lookup service: `worker/` (Cloudflare Worker, deploy steps in `worker/README.md`); its address goes in `LOOKUP_URL` in `src/lookup.js`, empty = lookup off
- Tests and browser checks that need several ISBNs use `test/fixtures/isbns.json` (valid real ISBNs and invalid ones); add new ones there instead of inventing them
- Verify UI changes in a real browser with `/verify-app` (needs the Playwright MCP from `.mcp.json`)
- Hook (`.claude/settings.json`): after edits to JS in `src/` or `test/`, `node --check` and `npm test` run automatically; a failure is reported back (exit code 2)

Ideas that are not in the current work go to `BACKLOG.md`.

## Constraints
- The interface is Ukrainian only (no language toggle): fixed text is written in `index.html`, every message built in code is in `src/strings.js` (Ukrainian plurals via `plural()`). The lists are «Шукане» (code: `scanned`) and «Вибране» (code: `marked`). Keep new texts concise.
- The app's only network call is the lookup in `src/lookup.js` (`GET <LOOKUP_URL>/lookup?isbn=…` to our own worker, which reads the Goodreads page's JSON-LD and answers `{title, series, author, rating, image, url}`). It runs in the background after the card is shown, once per ISBN per page load, 5 s timeout, no retries; every failure is silent, and the app must keep working fully without it (empty `LOOKUP_URL`). Open Library and Google Books stay out, and don't add a key or `config.js` without being asked. A found title only replaces the default `ISBN <number>`, never a typed name or an older stored title. The card shows what it found (`src/details.js`): the cover (an `<img>` with empty `alt`, removed if it fails to load; https only), the title without its trailing brackets, the rating as the accent (★ value, count), and the series (a Goodreads search for its name) and the first author (their Goodreads page) as links. Every field is validated in `cleanAnswer` before it is stored or rendered.
- Ereadian and Goodreads are link-only (`src/links.js`), shown as their icons (saved in `icons/`, see its README; never fetched at runtime, since their servers send no CORS headers): their pages can't be read from the browser and Ukrainian stores (Yakaboo, Rozetka) block scripts (403), so don't scrape them. The user can name a book by tapping its title on the card.
- Render user-supplied text (typed names, stored lists) only via `textContent`, never `innerHTML`.
- Keep it minimal: no frameworks, bundlers or npm dependencies. The one exception is the vendored `@zxing/browser` for barcode scanning (`vendor/`, see its README), loaded lazily only when Scan is pressed.
- State lives in the URL and in `localStorage`: `#isbn=<isbn>` deep-links a search (Back/Forward re-run it), `isbn-reader.scanned` holds every searched or scanned book (newest first; it replaced `isbn-reader.recent`, which is copied once on first load), `isbn-reader.marked` the "Marked" list (the ☆ on a card or a Scanned row), `isbn-reader.names` names the user typed for books (tap the title on the card to edit it; empty goes back to the found title, or `ISBN <number>`), `isbn-reader.meta` what the lookup found (a cache, capped at 1000; entries carry a version `v`, an older one is shown but asked again), `isbn-reader.theme` a light/dark override (absent = follow the device, via the theme button). Both lists hold at most 1000 books; a full list refuses new ones (the card is still shown, with a warning between it and the lists) and they share one list view (`src/listView.js`) and one store (`src/bookList.js`). Storage can be blocked, full or corrupt: reading it must never throw or stop the page from rendering.
- The camera must never start automatically, and the manual ISBN field must keep working when the camera is denied or unavailable. Camera access needs `localhost` or https.
