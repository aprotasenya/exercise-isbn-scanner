- **Automatic name and cover for books, taken from Ereadian (the app no longer has any book data source).** Blocked as a static page: the browser refuses to read ereadian.com from our origin (no CORS headers; checked for search and book pages, and a `no-cors` request comes back opaque with no body or headers, the same for found and not found), the search page cannot be framed (`X-Frame-Options: SAMEORIGIN`), its cover URLs are signed (`/img?...&s=...&k=...`, 403 without the signature) and `robots.txt` disallows `/img`, search URLs and `/api/`; its terms are unpublished. For now the user types a name on the unknown card. Options: ask Ereadian for an API or CORS access; a bookmarklet the user installs that reads the first result on the Ereadian tab and opens our app at `#isbn=…&title=…&cover=…` (accept only `https://ereadian.com/img?` covers, render via `textContent`); a local proxy (scraping, against the "no backend" rule, not recommended).
- **Book name and cover from Goodreads, through a tiny lookup service** (checked 2026-10-25; replaces the old "scrape with Beautiful Soup" idea). **Needs a decision** because it breaks "no backend" in `CLAUDE.md`.
  - **What Goodreads gives us.** `https://www.goodreads.com/book/isbn/<isbn>` redirects (301) to the book page, and the plain HTML (no JavaScript needed) holds a schema.org `Book` block, `<script type="application/ld+json">`, with the **full** `name`, `image`, `isbn`, `inLanguage`, `numberOfPages` and an `author` list (the Ukrainian edition of 9786171299412 gives "Шлях королів" and both "Brandon Sanderson" and "Брендон Сандерсон"). The `og:title` / `og:image` tags have the same data, but `og:title` is cut with "…" at about 60 characters, so prefer the JSON-LD. A book Goodreads doesn't know (9789661092999) answered with an empty HTTP 202 twice: treat any non-200 or empty body as "no data". robots.txt blocks only `/api`, `/book/reviews/` and `/book_link/follow/` for generic crawlers (terms of service not checked: read them before building).
  - **Why a service is needed.** The page has no CORS headers and is `x-frame-options: SAMEORIGIN`, so a browser page can't read it. The cover image host (`m.media-amazon.com`) does send `access-control-allow-origin: *`, so an `<img>` can show the cover once we know its URL.
  - **Smallest version: a hosted lookup function, about 40 lines** (e.g. a Cloudflare Workers free-tier function; no keys). It must be hosted, not a local script, because the app is used on a phone from the Pages site. `GET /lookup?isbn=<isbn>`: reject anything that is not a valid ISBN, fetch the Goodreads URL (follow the redirect, 5 s timeout, a plain browser-like User-Agent), find the JSON-LD block (a regex for the script tag plus `JSON.parse`, no HTML library), answer `{title, authors, image, url}` as JSON, or `404 {}` when there is nothing. It sends `Access-Control-Allow-Origin` for our Pages origin only (and `http://localhost:8000` while developing), caches answers (the platform's cache, for example 7 days, also for "not found" for a day) and refuses more than a few requests a second, so we stay a polite client.
  - **App side.** A `src/lookup.js` with the service URL in one constant. After a search or scan the card appears at once as today, and the lookup runs in the background (once per ISBN, 5 s timeout, no retries; a failure is silent and the card stays `ISBN <number>`). The result is saved under a new key such as `isbn-reader.meta` (ISBN to `{title, image}`, capped at 1000 like the lists). Title priority: the name the user typed, then the Goodreads title, then `ISBN <number>`. When a title arrives, the card heading and the Scanned/Marked rows are renamed only if they still show the default (never over a typed name; the existing `names`/`rename` logic can be reused), and a stale answer for a card that is no longer shown is dropped (like the old `searchId`). The cover is shown on the card as an `<img>` of the URL (with an empty `alt`, hidden if it fails). The lists keep their plain one-line rows. In Keep scanning the lookup must not slow the scan: beep, flash and "Додано" stay instant.
  - **Constraints to update if we do it.** `CLAUDE.md` currently says the app talks to no book API and has no backend: change it to say that the only allowed network call is this one lookup, that the app must keep working fully without it, and that Open Library and Google Books stay out. Add `/verify-app` checks (service mocked with `page.route`, since the checks must not depend on Goodreads), unit tests for the JSON-LD parsing and the title-priority rule, and a note in the README about the service and where it is deployed.
  - **Things to settle first:** where to host it (and who owns the account), whether to show the author too (the data has it), whether the Goodreads title may replace the stored `ISBN <number>` title in lists that already exist, and Goodreads' terms of service.
