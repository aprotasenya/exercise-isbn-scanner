Ideas that are not part of the current work. Move an item into the plan when it is next. Open Library was dropped from the app (2026-10-24), so ideas that needed it (title/author search, "More by…", live ISBN check, "add to Open Library") were removed; the Goodreads link is now part of the app.

## Needs a decision
- **Automatic name and cover for books, taken from Ereadian (the app no longer has any book data source).** Blocked as a static page: the browser refuses to read ereadian.com from our origin (no CORS headers; checked for search and book pages, and a `no-cors` request comes back opaque with no body or headers, the same for found and not found), the search page cannot be framed (`X-Frame-Options: SAMEORIGIN`), its cover URLs are signed (`/img?...&s=...&k=...`, 403 without the signature) and `robots.txt` disallows `/img`, search URLs and `/api/`; its terms are unpublished. For now the user types a name on the unknown card. Options: ask Ereadian for an API or CORS access; a bookmarklet the user installs that reads the first result on the Ereadian tab and opens our app at `#isbn=…&title=…&cover=…` (accept only `https://ereadian.com/img?` covers, render via `textContent`); a local proxy (scraping, against the "no backend" rule, not recommended).
- **Try Goodreads for book data: request `https://www.goodreads.com/book/isbn/{isbn}` and parse the HTML with Beautiful Soup** (https://www.crummy.com/software/BeautifulSoup/bs4/doc/). Beautiful Soup is a Python library, so this needs a small server-side script or service, which today's constraints rule out (static page, no backend, no dependencies); the browser alone can't read Goodreads (no CORS). To settle first: where it runs (a local helper script next to `python3 -m http.server`, or a throwaway experiment script that only prints title, author, rating and cover for the fixture ISBNs, which keeps the app untouched); Goodreads' terms and `robots.txt` (the same scraping concern as the stores: check before building anything on it); and whether the result is worth it compared with the plain Goodreads link the cards already have. Start as an experiment script in `scripts/`, not as an app feature.

## Later
- **Switch the barcode reader for a better one.** The current one (vendored `@zxing/browser`) performs poorly in low light and is slow. To research: the native `BarcodeDetector` API (hardware-accelerated where available, e.g. Chrome on Android) with the current library as a fallback; a newer WASM reader such as `zxing-wasm`; other libraries (Quagga2, `html5-qrcode`); commercial SDKs (Scandit, Dynamsoft) if free options fall short. Cheaper tweaks to try first: ask the camera for a higher resolution and continuous autofocus, a torch/flash toggle for dim shops, decode only EAN-13 (the current reader tries every 1D format), cropping or downscaling the frame, and tuning the decode rate. Measure on a real phone in poor light before choosing; `/verify-app`'s fake camera only proves the flow, not reading quality.
