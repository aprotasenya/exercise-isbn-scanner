# Backlog

Ideas that are not part of the current work. Move an item into the plan when it is next.

## Needs a decision
- **Automatic name and cover for books Open Library lacks, taken from Ereadian.** Blocked as a static page: the browser refuses to read ereadian.com from our origin (no CORS headers; checked for search and book pages, and a `no-cors` request comes back opaque with no body or headers, the same for found and not found), the search page cannot be framed (`X-Frame-Options: SAMEORIGIN`), its cover URLs are signed (`/img?...&s=...&k=...`, 403 without the signature) and `robots.txt` disallows `/img`, search URLs and `/api/`; its terms are unpublished. For now the user types a name on the unknown card. Options: ask Ereadian for an API or CORS access; a bookmarklet the user installs that reads the first result on the Ereadian tab and opens our app at `#isbn=…&title=…&cover=…` (accept only `https://ereadian.com/img?` covers, render via `textContent`); a local proxy (scraping, against the "no backend" rule, not recommended).

## Later
- **Switch the barcode reader for a better one.** The current one (vendored `@zxing/browser`) performs poorly in low light and is slow. To research: the native `BarcodeDetector` API (hardware-accelerated where available, e.g. Chrome on Android) with the current library as a fallback; a newer WASM reader such as `zxing-wasm`; other libraries (Quagga2, `html5-qrcode`); commercial SDKs (Scandit, Dynamsoft) if free options fall short. Cheaper tweaks to try first: ask the camera for a higher resolution and continuous autofocus, a torch/flash toggle for dim shops, decode only EAN-13 (the current reader tries every 1D format), cropping or downscaling the frame, and tuning the decode rate. Measure on a real phone in poor light before choosing; `/verify-app`'s fake camera only proves the flow, not reading quality.
- **Snap a cover photo with the camera** for books without a cover (e.g. the unknown ones Open Library and Ereadian can't give us): needs research first. Open questions: capture with `getUserMedia` into a canvas, downscaled to a small JPEG; where to keep it (`localStorage` is about 5 MB and data URLs add up, so probably IndexedDB, plus cleanup when a book is unmarked); showing it on the card and in the Marked list; whether the JSON export should include images (size) or skip them; privacy (images stay in the browser); should a photo also be offered for found books that lack a cover; how it interacts with the barcode scanner (a second camera mode, and a framing guide).
- **Live ISBN check script** (e.g. `scripts/check-isbns.mjs`, run on demand and not part of `npm test`): resolve every entry of `test/fixtures/isbns.json` against Open Library and report entries whose result no longer matches (`found` must resolve, `notFoundInOpenLibrary` must not, `invalid` must fail the checksum). The offline tests can't verify those claims; today they rest on a one-off live check and `/verify-app`.
